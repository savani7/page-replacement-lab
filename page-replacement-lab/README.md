# Page Replacement Lab
An interactive Operating Systems learning simulator for **FIFO**, **LRU** and **Optimal** page replacement.
Light theme, large RAM boxes, automatic animation, step-by-step explanations. No internet or paid services needed.

## Run it on Windows (VS Code)

1. Install Python 3.10+ from python.org (tick **"Add Python to PATH"**; the default installer includes Tkinter).
2. Unzip the project, then in VS Code: **File → Open Folder → `page-replacement-lab`**.
3. Open a terminal (**Terminal → New Terminal**) and run:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

If PowerShell blocks `activate`, run `Set-ExecutionPolicy -Scope Process Bypass` first (or use Command Prompt).

## Run the tests (no extra install needed)

```powershell
python -m unittest discover -s tests -t . -v
```
(`pytest` also works if you install it.)

## How to use
* **Interactive Simulator** – type a reference string (e.g. `1, 2, 3, 1, 4, 2, 5`), frames (1–8), pick an algorithm,
  click **START SIMULATION**. The whole run plays automatically. Use Pause / Resume / Restart, the speed slider,
  or tick *Manual-step mode* and press *Next step*.
* **Algorithm Battle Arena** – FIFO, LRU and Optimal run side by side in sync, then a results table highlights the
  algorithm with the fewest faults and explains the comparison.
* **Learn Page Replacement** – concepts, FIFO / LRU / Optimal lessons, worked examples (generated by the real algorithms) and a comparison table.
* **Quiz & Viva** – 10 random questions per attempt with explanations, score and retry; plus viva Q&A.

## What you see for each reference
`incoming` (page arrives) → `decide` (victim highlighted in coral, reason shown) → `remove` (victim marked REMOVED)
→ `enter` (a token slides into the frame, new page in blue) → `done` (result in green, statistics update).
Hits and free-frame loads use a shorter sequence. The RAM BEFORE / RAM AFTER strip shows the transformation.

## Project structure
```
main.py                 app window + screen switching
algorithms/             pure Python logic (no GUI): base.py, fifo.py, lru.py, optimal.py, compare.py
ui/                     panel.py (RAM boxes + animation), playback.py (after()-based timer),
                        simulator.py, battle_arena.py, dashboard.py, learning_*.py, quiz*.py, styles.py
tests/                  unit tests for algorithms, validation, playback (pause/resume/restart/replay)
```
All explanations are generated from the real algorithm state; nothing is hard-coded per example.

## Note on the expected results
For `1, 2, 3, 1, 4, 2, 5` with 3 frames the correct fault counts are **FIFO 5, LRU 6, Optimal 5**
(worked by hand and verified by the tests). FIFO evicts page 1 at reference 5, so page 2 is still resident at
reference 6 and that reference is a hit. Optimal's tie-break among never-used-again pages is "lowest-numbered frame".

## Honest testing notes
* Algorithms, validation, comparison and the playback controller (pause, resume, restart, replay, manual mode) are covered by unit tests.
* `tests/test_ui_logic_with_stub_widgets.py` runs the real screen code against fake widgets – it checks the wiring, not how it looks.
* The graphical window itself must be checked by launching `python main.py`.
